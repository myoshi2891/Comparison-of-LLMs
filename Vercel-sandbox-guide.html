Section 01

Vercel Sandbox とは？

Vercel Sandbox は、AI エージェントが生成したコード・ユーザーが入力したスクリプト・サードパーティ製コードなど、信頼できないコードを完全に隔離された Linux マイクロVM内で安全に実行するためのサービスです。2026年1月30日に GA（一般公開）となり、CLI と SDK はオープンソース化されました。

💡
一言で言うと: 「コードを安全に動かせる使い捨ての Linux マシン」を数ミリ秒で用意できるサービスです。従来のコンテナよりも強力な VM レベルの隔離を実現しています。

Vercel Sandbox が解決する課題

従来インフラの問題 Vercel Sandbox の解決策
環境準備に数分かかる ⚡ ミリ秒単位で起動（サブ秒）
実行環境が共有され攻撃リスクが高い 🔒 Firecracker MicroVM による完全分離（独自カーネル）
アイドル時間にもコストがかかる 💰 Active CPU 時間のみ課金
複雑な環境の状態引き継ぎが困難 📸 自動スナップショットで状態を保存・復元
本番環境への意図しない影響リスク 🌐 完全に隔離された VM のため本番への影響ゼロ

システム仕様

項目 詳細
ベース OS Amazon Linux 2023
利用可能ランタイム node26, node24（デフォルト）, node22, python3.13
デフォルト作業ディレクトリ /vercel/sandbox
実行ユーザー vercel-sandbox（sudo アクセス可）
仮想化技術 Firecracker MicroVM（各 VM が独自カーネルを保有）
起動速度 ミリ秒単位（サブ秒）
最大 vCPU 8 vCPU（各 vCPU に 2048 MB RAM）
最大公開ポート数 15 ポート
プリインストールツール git, curl, unzip, tar, openssl 等
Section 02

全体アーキテクチャを理解する

Vercel の内部コンピュートプラットフォーム「Hive」は、毎日 270万件以上のデプロイを処理する基盤の上に Sandbox を構築しています。SDK・CLI から Firecracker MicroVM まで、呼び出しがどのように流れるかを把握しましょう。

Vercel Sandbox の多層アーキテクチャ — 呼び出し元から Firecracker MicroVM まで

⚠️
コンテナとの違い: Docker などのコンテナはホスト OS のカーネルを共有しますが、Vercel Sandbox は各 VM が独自のカーネルを持つ Firecracker MicroVM のため、より強力な隔離が実現されています。

Section 04

セットアップ手順（Step-by-Step）

5 つのステップで Vercel Sandbox を使い始められます。

1
Vercel CLI のインストール
Vercel CLI をグローバルインストールします。
bash 
npm install -g vercel
2
プロジェクトの作成・リンク（認証の準備）
vercel link で プロジェクトとリンクすることで OIDC トークン認証が使えるようになります。
bash 
mkdir my-sandbox-project && cd my-sandbox-project

# Vercel にリンク（OIDC トークン認証を有効化）
vercel link

# 環境変数を取得（VERCEL_OIDC_TOKEN が .env.local に保存される）
vercel env pull
⚠️
重要: OIDC トークンは 12時間で失効します。長時間の開発では vercel env pull を再実行してください。
3
Sandbox CLI / JS SDK のインストール
bash 
# CLI をグローバルインストール
npm install -g sandbox

# または npx で直接使用（インストール不要）
npx sandbox --help

# JS SDK をプロジェクトに追加
npm install @vercel/sandbox

# Python SDK の場合
pip install vercel
4
認証方法を選択する
認証方法 使用環境 セキュリティ 設定コマンド
OIDC Token（推奨） Vercel 上・ローカル開発 ◎ 自動ローテーション vercel link && vercel env pull
Access Token 外部 CI/CD・非 Vercel 環境 ○ 長期間有効 Dashboard で手動生成
5
最初の Sandbox を作成する
CLI で 1 コマンドか、JS SDK で数行のコードで起動できます。
bash 
# CLI で最速スタート（作成してシェルに接続）
npx sandbox create --connect
Section 05

コアコンセプト：Sandbox と Session

Vercel Sandbox を使いこなすために、Sandbox・Session・Snapshot の 3 つの概念を理解しましょう。

Sandbox（長期的な存在）の中で Session（単一の VM 起動）が繰り返される

概念 説明 ライフタイム
Sandbox name で識別される長期的な存在。設定・Snapshot を保持 プロジェクトが存在する限り
Session Sandbox 内で起動する単一の VM インスタンス コマンド実行中〜停止まで
Snapshot Session 停止時に自動保存されるファイルシステムの状態 設定した有効期限まで
Section 06

永続的 vs 一時的サンドボックス

Vercel Sandbox にはデフォルトの Persistent（永続） モードと、一時タスク向けの Non-persistent（一時） モードがあります。

観点 Persistent（デフォルト） Non-persistent
停止時の挙動 ✅ 自動スナップショット保存 ❌ 状態は破棄
再開方法 Sandbox.get({ name }) で自動再開 不可（新規作成のみ）
スナップショット管理 自動（手動管理不要） なし
ストレージ課金 Snapshot Storage が発生 発生しない
主な用途 開発環境・エージェントワークスペース・長期ジョブ CI/CD・ビルド専用・使い捨てタスク
作成時の指定 デフォルト（省略可） persistent: false または --non-persistent
Section 07

はじめての Sandbox を作る

CLI で最速スタート（1コマンド）

bash 
# Sandbox を作成してインタラクティブシェルに接続
npx sandbox create --connect

# 名前を指定して作成
sandbox create --name my-first-sandbox --connect

JS SDK で最小コード

typescript 
import { Sandbox } from "@vercel/sandbox";

async function main() {
  // 1. サンドボックスを作成（persistent がデフォルト）
  const sandbox = await Sandbox.create({
    name: "my-first-sandbox",    // 省略するとランダム名が生成される
    runtime: "node24",           // デフォルトは node24
    timeout: 5 * 60 * 1000,     // タイムアウト: 5分（ミリ秒単位）
  });

  // 2. コマンドを実行
  const result = await sandbox.runCommand("node", [
    "-e",
    'console.log("Hello from Vercel Sandbox!")',
  ]);
  console.log("Exit code:", result.exitCode);       // 0
  console.log("Output:", await result.stdout());    // Hello from...

  // 3. 停止（persistent なので自動スナップショット保存）
  await sandbox.stop();
}

main();

作成〜実行フロー

Sandbox 作成から停止まで全体フロー

Section 08

JS SDK 実践ガイド

主要メソッド一覧

メソッド 用途 戻り値
Sandbox.create() 新規 Sandbox を作成 Promise<Sandbox>
Sandbox.get() 既存 Sandbox を名前で取得 Promise<Sandbox>
Sandbox.getOrCreate() あれば再開・なければ作成（推奨） Promise<Sandbox>
Sandbox.fork() 既存 Sandbox をフォーク Promise<Sandbox>
Sandbox.list() Sandbox 一覧を取得（async-iterable） Promise<Paginated>
sandbox.runCommand() コマンドを実行 Promise<CommandFinished>
sandbox.writeFiles() ファイルを書き込む Promise<void>
sandbox.readFileToBuffer() ファイルを読み込む Promise<Buffer|null>
sandbox.domain() 公開 URL を取得 string
sandbox.stop() Sandbox を停止 Promise<...>
sandbox.update() 設定を動的に更新 Promise<void>
sandbox.delete() 完全削除（Snapshot も消去） Promise<void>
sandbox.extendTimeout() タイムアウト延長 Promise<void>
sandbox.snapshot() 手動スナップショット Promise<Snapshot>

パターン A：一時タスク向け（Non-persistent）

typescript 
const sandbox = await Sandbox.create({
  persistent: false,            // 停止後に状態を破棄（Snapshot 課金なし）
  timeout: 15 * 60 * 1000,     // 15分
});

try {
  await sandbox.runCommand("npm", ["test"]);
} finally {
  await sandbox.stop();         // 状態は破棄される
}

パターン B：長期利用向け getOrCreate（最推奨）

getOrCreate の 3 つの動作分岐

typescript 
const sandbox = await Sandbox.getOrCreate({
  name: "dev-environment",
  runtime: "node24",

  // 🔴 初回作成時のみ実行（重い初期化）
  onCreate: async (sbx) => {
    await sbx.runCommand("git", ["clone", "https://github.com/your/repo", "."]);
    await sbx.runCommand("npm", ["install"]);
    console.log("初回セットアップ完了！（次回から skip）");
  },

  // 🔵 再開のたびに実行（バックグラウンドサービスの再起動等）
  onResume: async (sbx) => {
    await sbx.runCommand({
      cmd: "npm",
      args: ["run", "dev"],
      detached: true,           // バックグラウンドで実行
    });
    console.log("Dev サーバー起動！");
  },
});

ファイル操作

typescript 
// ファイルの書き込み
await sandbox.writeFiles([
  {
    path: "/vercel/sandbox/src/index.ts",
    content: Buffer.from(`export const hello = () => "world";`),
  },
  {
    path: "/vercel/sandbox/scripts/run.sh",
    content: Buffer.from("#!/bin/bash\nnpm start"),
    mode: 0o755,                // 実行権限を付与（chmod +x 相当）
  },
]);

// ファイルの読み込み
const buf = await sandbox.readFileToBuffer({ path: "dist/output.js" });
if (buf) console.log(buf.toString());

// ローカルにダウンロード
await sandbox.downloadFile(
  { path: "/vercel/sandbox/coverage/lcov.info" },
  { path: "./reports/lcov.info", mkdirRecursive: true }
);

ポート公開（Dev サーバーのプレビュー URL）

typescript 
const sandbox = await Sandbox.create({
  name: "web-preview",
  ports: [3000, 8080],           // 公開するポート番号
});

// Dev サーバーをバックグラウンドで起動
await sandbox.runCommand({
  cmd: "npm",
  args: ["run", "dev"],
  detached: true,
});

// 公開 URL を取得
const previewUrl = sandbox.domain(3000);
console.log("プレビュー URL:", previewUrl);
// => https://xxxxxxxx-3000.sandbox.vercel.app
Section 09

CLI 完全リファレンス

コマンド全体マップ

sandbox CLI の全コマンド体系

よく使うコマンド実例

bash 
# ─── 作成 ──────────────────────────────────────────────
# 基本（Node.js 24）
sandbox create --name my-sandbox

# Python ランタイムで 1 時間タイムアウト
sandbox create --runtime python3.13 --timeout 1h --name py-box

# 作成と同時にシェルに接続
sandbox create --name dev-box --connect

# ポートを公開（Dev サーバー向け）
sandbox create --name web-app --publish-port 3000

# 非永続（一時）サンドボックス
sandbox create --name ci-task --non-persistent

# Snapshot 7日保持 + 最新1件のみ
sandbox create --name long-lived \
  --snapshot-expiration 7d \
  --keep-last-snapshots 1

# ─── コマンド実行 ───────────────────────────────────────
# 停止中でも自動再開してからコマンド実行
sandbox run --name my-sandbox -- npm test

# 起動中の Sandbox にコマンドを送信
sandbox exec my-sandbox -- node script.js

# sudo でシステムパッケージをインストール
sandbox exec --sudo my-sandbox -- dnf install -y curl

# インタラクティブシェルに接続
sandbox connect my-sandbox

# ─── ファイル操作 ──────────────────────────────────────
# ローカル → Sandbox
sandbox copy ./local.txt my-sandbox:/vercel/sandbox/remote.txt

# Sandbox → ローカル
sandbox copy my-sandbox:/vercel/sandbox/output.log ./logs/

# ─── 設定変更 ──────────────────────────────────────────
sandbox config list my-sandbox           # 現在の設定を確認
sandbox config vcpus my-sandbox 4        # 4 vCPU に変更
sandbox config timeout my-sandbox 30m   # タイムアウト 30 分
sandbox config tags my-sandbox --tag env=staging --tag team=backend

# ─── 停止・削除 ────────────────────────────────────────
sandbox stop my-sandbox                  # 停止（Snapshot 保存）
sandbox remove my-sandbox               # 完全削除（Snapshot も消去）

run vs exec の違い

コマンド 対象 Sandbox の状態 動作
sandbox run 停止中・起動中どちらでも OK 停止中なら 自動的に再開してから実行
sandbox exec 起動中のみ 停止中の場合はエラー
Section 10

永続的サンドボックスの詳細

ライフサイクル全体フロー（シーケンス）

停止 → スナップショット → 再開 の完全なシーケンス

ライフサイクルフック（onCreate と onResume）

フック 実行タイミング 用途
onCreate Sandbox が初回作成されたときのみ 重い初期化（git clone、npm install 等）
onResume 毎回の再開時（自動再開も含む） バックグラウンドサービスの再起動、キャッシュの再読み込み
typescript 
const sandbox = await Sandbox.getOrCreate({
  name: "agent-workspace",

  // ✅ 初回のみ（重い処理）
  onCreate: async (sbx) => {
    await sbx.runCommand("git", ["clone", repoUrl, "."]);
    await sbx.runCommand("npm", ["install"]);
    await sbx.runCommand("pip", ["install", "-r", "requirements.txt"]);
  },

  // ✅ 毎回の再開時（軽量な再起動）
  onResume: async (sbx) => {
    await sbx.runCommand({ cmd: "redis-server", detached: true });
    await sbx.runCommand({ cmd: "npm", args: ["run", "dev"], detached: true });
  },
});
Section 11

スナップショット管理

スナップショット保持ポリシーのフロー

推奨設定（コスト最小化）

typescript 
// ✅ 最新 1 件のみ保持してストレージコストを最小化
const sandbox = await Sandbox.create({
  name: "my-sandbox",
  snapshotExpiration: 7 * 24 * 60 * 60 * 1000,   // 7日
  keepLastSnapshots: {
    count: 1,               // 最新 1 件のみ
    deleteEvicted: true,    // 古いものは即座に削除
  },
});

スナップショット操作コマンド

bash 
# 手動でスナップショットを作成
sandbox snapshot my-sandbox

# スナップショット一覧を表示
sandbox snapshots list my-sandbox

# 特定スナップショットに巻き戻し
sandbox config current-snapshot my-sandbox snap_abc123

# 特定スナップショットから新規 Sandbox を作成
sandbox create --name forked-sandbox --snapshot snap_abc123

# 既存 Sandbox をフォーク（スナップショットを継承）
sandbox fork my-sandbox --name my-fork
Section 12

ネットワークポリシー

3 種類のポリシー

ポリシー 説明 用途
allow-all すべての通信を許可（デフォルト） 開発・テスト
deny-all すべての通信を遮断 最高セキュリティが必要な実行
カスタム ドメイン / CIDR を個別指定 特定 API のみ許可
bash 
# すべて遮断（最もセキュア）
sandbox create --name secure-box --network-policy deny-all

# Vercel AI ゲートウェイのみ許可
sandbox create --name ai-box --allowed-domain ai-gateway.vercel.sh

# ワイルドカードでサブドメインを許可
sandbox create --name api-box \
  --allowed-domain "*.vercel.app" \
  --allowed-domain api.example.com

# 実行後に設定変更（動的に変更可能）
sandbox config network-policy my-sandbox --mode deny-all
Section 13

タグによる管理

タグ（Tags）は Sandbox を 環境・チーム・用途 などで分類するためのキーバリューペアです（最大 5 個）。

タグを使ったフリート管理の例

bash 
# 作成時にタグを付与
sandbox create --name prod-sandbox \
  --tag env=production \
  --tag team=backend \
  --tag version=2.0

# タグでフィルタして一覧表示
sandbox list --tag env=staging

# タグを更新（既存タグはすべて置き換え）
sandbox config tags my-sandbox \
  --tag env=production \
  --tag team=platform

# タグをすべてクリア
sandbox config tags my-sandbox
Section 14

ベストプラクティス集

全体像

✅ BP-1：Snapshot は最新 1 件のみ保持（コスト最小化）

❌ 悪い例
typescript 
// Snapshot が無制限に蓄積される
await Sandbox.create({ name: "my-sandbox" });
✅ 良い例
typescript 
// 最新 1 件のみ保持してコスト最小化
await Sandbox.create({
  name: "my-sandbox",
  snapshotExpiration: 7 * 24 * 60 * 60 * 1000,
  keepLastSnapshots: { count: 1, deleteEvicted: true },
});

✅ BP-2：CI/CD の使い捨てタスクは Non-persistent

❌ 悪い例
typescript 
// CI で永続モード → 不要な Snapshot 課金
await Sandbox.create({ name: "ci-run-123" });
✅ 良い例
typescript 
// non-persistent で課金ゼロ
await Sandbox.create({
  name: "ci-run-123",
  persistent: false,
  timeout: 15 * 60 * 1000,
});

✅ BP-3：getOrCreate で冪等性を確保

❌ 悪い例
typescript 
// 2 回目は同名 Sandbox が既に存在しエラー
const sb = await Sandbox.create({ name: "dev" });
✅ 良い例
typescript 
// 「あれば再開・なければ作成」で常に安全
const sb = await Sandbox.getOrCreate({ name: "dev" });

✅ BP-4：name は必ず明示的に指定

❌ 悪い例
typescript 
// ランダム名 → 後で管理が困難
await Sandbox.create();
✅ 良い例
typescript 
// ユーザー ID 等を含めた意味のある名前
await Sandbox.create({
  name: `user-${userId}-workspace`,
  tags: { userId, env: "development" },
});

✅ BP-5：タイムアウトを用途に合わせて設定

用途 推奨タイムアウト 設定例
インタラクティブ開発 長め（1時間） --timeout 1h
AI エージェントのタスク 中程度（30分） --timeout 30m
CI/CD ビルド 短め（15分） --timeout 15m
デフォルト 5分 省略可
